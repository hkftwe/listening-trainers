# Listening Trainers — Minimal Pair Auditory Discrimination

Self-contained, single-file HTML trainers for English phoneme discrimination. Open in any browser (desktop or mobile) — no server, no install, no dependencies. Uses the browser's built-in speech synthesis (TTS) with multi-voice rotation to simulate high-variability phonetic training (HVPT).

The index page (`index.html`) links all trainers for easy access on mobile.

## Architecture

Trainers are built from a shared template, not maintained as independent copies:

```
template.html          ← shared UI, game logic, report export, TTS engine
data/*.csv             ← trainer-specific word banks (one CSV per contrast)
build-trainers.py      ← merges template + CSV → writes HTML to dist/
manual/                ← manually maintained HTML not generated by the script
index.html             ← navigation page (auto-regenerated by build-trainers.py)
```

**Generated** (`dist/`): tr-ch, fr-fire, nl, nl-core, f-th, f-th-focused, f-th-simple — these are built by `build-trainers.py`. To modify them, edit the CSV in `data/` or the shared `template.html`, then re-run `python3 build-trainers.py`.

**Manual** (`manual/`): v-f-listening-trainer.html — built manually before the CSV generator supported it. When it moves to data-driven generation, the manual copy can be removed.

## How It Works

Each trainer presents a series of auditory discrimination questions. The browser speaks a word (or sentence) using randomly rotated TTS voices, and you identify which sound you heard.

### Standard Progression (3 stages)

1. **Stage 1 — Core Pairs (3–8 pairs)**  
   Small, focused set to build initial discrimination. Isolated words only.

2. **Stage 2 — Expanded Word Bank (8–16 pairs)**  
   Larger pool introducing words not in Stage 1. Must score ≥80% in Stage 1 to unlock.

3. **Stage 3 — Words in Sentences**  
   Full sentences — identify the target sound in the key word. Tests discrimination in connected speech.

### Variant Trainers (1–2 stages)

Focused and core variants skip or combine stages for specific training needs:
- **core** variants: drill only the highest-frequency, most problematic words from the full trainer
- **focused** variants: pure-sound discrimination without preview text (words shown only after answering)

Each round is 10 questions. Voices rotate randomly across TTS engines available in your browser (Samantha, Daniel, Karen, Alex, Moira, etc. on macOS/iOS).

## Features

- **Multi-voice TTS rotation** — each question uses a different voice when available, providing natural acoustic variability
- **Stage locking** — Stage N+1 unlocks when Stage N reaches 80%+ accuracy
- **Preview before answering** — see the word (and IPA) before the question begins (standard mode; focused variants hide the preview)
- **Immediate feedback** — correct/incorrect with IPA shown after each answer
- **Review table** — all 10 questions with your answers vs correct answers shown after each round
- **Export report** — generates a structured text report for sharing with a teacher
- **Keyboard shortcuts** — Space to play, ←/→ to answer, Enter to advance
- **Mobile-friendly** — responsive layout, works on phone browsers
- **History tracking** — all answers stored in session; summary stats per stage

## Usage

1. Open any `.html` file from `dist/` in a browser (double-click or `open dist/tr-ch-listening-trainer.html`)
2. Tap/click the play button or press Space to hear a word
3. Choose which sound you heard
4. After 10 questions, review your results
5. Score ≥80% to unlock the next stage (if applicable)
6. Use "Export Report" to save results

For mobile use, open `index.html` from a static file server or GitHub Pages, then navigate in your phone's browser.

## Technical Notes

- Uses the [Web Speech API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Speech_API) (`SpeechSynthesis`)
- Voice availability depends on your OS and browser. macOS/iOS have the richest built-in voices.
- All data stays in your browser — no tracking, no network requests, no server
- Each built file is ~1,500 lines, fully self-contained (HTML + CSS + JS)
- `build-trainers.py` requires Python 3; only the standard library is needed

## Why This Exists

These trainers were built because:

1. **Receptive phonological awareness must come before production.** If you can't hear the difference between /tr/ and /tʃ/, /v/ and /f/, or /n/ and /l/, you can't reliably produce it. Most pronunciation tools focus on production (speaking into a mic) and skip this foundational step.

2. **Existing HVPT tools are closed-source or require logins.** Linguatorium Auris, English Accent Coach, and similar academic tools are not available as self-hosted open-source projects.

3. **Browser TTS is good enough now.** Modern speech synthesis (especially on macOS/iOS) is clear enough for phoneme discrimination training, and it provides the multi-talker variability that HVPT research shows is essential.

4. **Single HTML files are the simplest deployment format.** No npm, no build step, no server. Just open the file. Works on phones.

5. **Quantified, trackable progress.** Each trainer produces a structured report with per-word error analysis, enabling data-driven SRS scheduling and comparison across sessions. This feedback loop has been validated across five phoneme contrasts over 20+ training sessions.

## Contributing

To add a new phoneme contrast using the data-driven pipeline:

1. Create a CSV file in `data/` with columns: `word`, `sound` (a/b), `ipa`, `stage` (1/2/3), `sentence` (for stage 3)
2. Add an entry to the `TRAINERS` dict in `build-trainers.py` with the new contrast's config
3. Run `python3 build-trainers.py` to generate the HTML and update `index.html`

To modify an existing trainer's word bank, edit the CSV in `data/` and re-run the build script. To change UI behavior, edit `template.html`.

For one-off or experimental trainers that don't fit the template, place them in `manual/`.

Pull requests for new phoneme contrasts, additional words, or UX improvements are welcome.
